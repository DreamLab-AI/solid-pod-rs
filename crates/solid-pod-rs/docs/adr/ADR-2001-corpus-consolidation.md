# ADR-2001 — Consolidate the ADR corpus into a code-grounded baseline

## Context

The crate's ADR corpus (ADR-057 … ADR-061) had drifted from the shipped code.
The records used freeform `Status:` lines (`partial-parity`, `Accepted`,
`Proposed`) that did not map to a maturity model, cited `lib.rs` line offsets
that no longer resolved (the server grew to ~5,059 lines), listed security items
as open gaps that had since shipped, and described provenance as "always-on"
while the default build records nothing. Readers could not tell decision from
implementation from activation.

## Decision

Replace the freeform corpus with one **code-grounded living baseline**
(`docs/BASELINE-solid-pod-rs.md`, `verified_commit` 0ccad60) plus a thin ADR
ledger using a three-axis status frontmatter (decision / implementation /
activation). The five legacy records are `git mv`-d unchanged to
`docs/archive/adr/` under a frozen tombstone and become citable evidence, never
authority. New decisions copy `TEMPLATE.md`, take the next free number, and must
update the baseline in the same change. The index is regenerated by
`scripts/adr-index-gen.js`, which fails CI on invalid frontmatter.

## Consequences

- The baseline is now the single lookup surface; the archive is history only.
- Drift is captured explicitly (baseline "Known divergences"): the LWS10 OIDC
  delta is unshipped, ADR-058's security gaps are all closed, provenance is
  off by default, no pod-wide `_prov` index exists, and legacy line citations
  are superseded.
- Every future decision carries an honest three-axis status and a
  `verified_commit`, so an ADR cannot silently overclaim.
- Cost: the baseline must be updated in lockstep with the surfaces it governs;
  a stale `verified_commit` is now the visible failure mode.

## Verification

- `git mv` of ADR-057…061 into `docs/archive/adr/` (five records), tombstone
  `README.md` written.
- Baseline claims spot-checked against code at 0ccad60:
  `oidc/mod.rs:184` (no EdDSA in discovery), `oidc/mod.rs:864` (no `cnf.webid`),
  `security/dotfile.rs:24` (`.account` present), `multitenant.rs:181-198`
  (iterative scrub), `wac/parser.rs:23-39` (ACL size cap),
  `solid-pod-rs-server/Cargo.toml:123` + `lib.rs:3490` (git off by default),
  `auth/replay_store.rs:68` (`ReplayStore` seam).
- `node scripts/adr-index-gen.js crates/solid-pod-rs/docs/adr` exits 0.

## Closeout extension — 2026-09-04

Work packages: CP-01/08. Accountable owner: the existing owner above, with storage, identity and release maintainers for consumer acceptance. Historical status axes and verified commits are preserved; no deployment is re-certified.

The consolidated pack is a documentation boundary. Structural index validity and historical verified commits do not certify the currently consumed feature sets or remote deployments.

**Acceptance condition:** Bind source, resolved consumer dependency, feature configuration and deployed artefact identities. Preserve the five frozen records as history and give each unresolved claim an explicit disposition. Keep scoped component completion distinct from complete-system acceptance.

Dependencies: CP-01 release identity and CP-04 effective authority. Reopen when the governed implementation, adapter, dependency, feature or deployment profile changes. See the [storage review](../../../../../VisionFlow/docs/estate-review/storage-and-authority.md) and [source revalidation](../../../../../VisionFlow/docs/estate-review/evidence/pod-closeout-snapshot.json). Scoped implementation status does not close these cross-service requirements.
